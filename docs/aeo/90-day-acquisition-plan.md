# Tera Earlywine: 90-Day AEO Acquisition Plan

## Commercial objective

Make Tera Earlywine the clearest credible answer when an enterprise buyer looks for help with production-grade data and AI in regulated, high-consequence operations—and turn that discovery into qualified fit calls.

The first 90-day outcome target is:

- 4 qualified fit calls
- 2 paid-diagnostic or project proposals
- 1 consulting engagement worth at least $25,000

A qualified lead has a specific costly problem, a plausible budget owner, a decision window, and a credible path to at least $25,000 in opportunity value.

## Message hierarchy

Use the following language consistently across the website, LinkedIn, GitHub, speaker biographies, podcast introductions, directories, and contributed articles.

**Name:** Tera Earlywine

**Role:** Independent Data & AI Consultant

**Category:** Production-grade data and AI for regulated, high-consequence operations

**Plain-English promise:** I fix the data systems your reporting, compliance, and AI depend on.

**Commercial breadth:** Data-platform modernization, reliability and migration rescue, AI-ready data foundations, production AI systems, governance, and fractional platform leadership.

**Primary CTA:** Book a fit call

## Days 0–7: Establish one source of truth

- Launch the revised `teraearlywine.com` homepage with consistent visible copy, JSON-LD, FAQ answers, sanitized proof, and fit-call CTAs.
- Align the GitHub profile README with the site.
- Replace the LinkedIn headline with: `Independent Data & AI Consultant | Production-grade systems for regulated operations | ex-Block, ex-Mercari`.
- Replace the first two lines of LinkedIn About with the homepage promise and specialty. Add the four problem categories and one fit-call link.
- Confirm that the site is accessible to Googlebot, Bingbot, `OAI-SearchBot`, and `PerplexityBot`. The existing `User-agent: * / Allow: /` policy permits them; verify server or WAF logs are not blocking their published IP ranges.
- Submit the homepage through Google Search Console URL Inspection and Bing Webmaster Tools. Use IndexNow only after ownership-key setup; never treat successful submission as proof of indexing.
- Record day-zero answers and cited URLs for the query set below.

## Days 8–21: Publish three proof pages

Each case study gets its own canonical page, a short LinkedIn version, and one CTA. Use the same name, role, and category language without copy-pasting entire paragraphs.

### Case study 1: Modernizing 500+ data workflows without breaking production

Cover the starting risk, migration shape, operating constraints, sequencing, validation, and sanitized outcome. Do not name confidential systems, internal incidents, or client-only metrics.

### Case study 2: Moving an on-call AI workflow from prompts into governed infrastructure

Explain why state, authorization, handoffs, recovery, and completion checks belong in deterministic services. Describe the architecture and decision framework without publishing Block-internal implementation details.

### Case study 3: Finding $500K+ in data-infrastructure efficiency

Explain the diagnosis, workload patterns, optimization method, guardrails, and measurement. Attribute the result only to the extent supported by public or approved material.

## Days 22–45: Own the problem language

Publish one substantial article per week on the site, with a sharper LinkedIn adaptation that links back to the canonical article.

1. `Your AI pilot does not have a prompting problem. It has an operations problem.`
2. `The migration is not late because the SQL is hard.`
3. `What auditability actually means for an agentic workflow.`
4. `A data contract is an operating agreement, not a YAML file.`

Every article should answer one buyer question in the first 100 words, include a concrete framework or example, link to a relevant case study, and end with the fit-call CTA. Write like Tera: direct, mildly opinionated, useful, and allergic to consultant fog.

## Days 46–70: Add independent corroboration

- Secure two appearances where another domain names Tera and the specialty: a data-engineering podcast, guest article, webinar, conference session, or expert interview.
- Ask three former colleagues or consulting partners for LinkedIn recommendations tied to reliability, modernization, governance, AI productionization, or technical leadership.
- Update high-authority profiles that already rank for the name. Correct stale employer and role data. Request removal of exposed personal phone numbers and obsolete personal or employer email addresses from data-broker pages.
- Add the exact canonical website URL and current role to every profile that permits it.
- Prefer a small number of relevant mentions over generic directory submissions. Do not buy backlinks or publish mass-produced guest posts.

## Days 71–90: Measure answers and tighten acquisition

Run the query set once per month in a clean or logged-out context where possible. Record whether Tera is mentioned, the description used, cited URLs, competing people or firms, and factual errors. A citation is useful only if the surrounding answer expresses the intended category accurately.

Review the funnel weekly:

`answer/search impression → site visit → booking click → fit call → qualified opportunity → proposal → win`

Keep the precise category if qualified leads understand it. Broaden supporting copy—not the core identity—when adjacent buyers convert. Change the core category only if 90 days of real conversations show that it blocks otherwise qualified demand.

## Evidence rules

- Use named, sanitized outcomes only.
- Keep structured data identical in substance to visible page content.
- Do not publish private client data, system names, incidents, screenshots, or metrics without explicit approval.
- Do not manufacture citations, testimonials, client logos, or awards.
- Do not promise answer-engine rankings or lead volume.
- Treat buyer conversations and qualified pipeline as the final signal; visibility without acquisition is not the goal.

## Source notes

- OpenAI documents that `OAI-SearchBot` is the crawler used to surface websites in ChatGPT search and recommends allowing it in `robots.txt`: https://developers.openai.com/api/docs/bots
- Perplexity recommends allowing `PerplexityBot` and permitting its published IP ranges for search visibility: https://docs.perplexity.ai/docs/resources/perplexity-crawlers
- Google recommends JSON-LD and requires structured data to truthfully represent visible page content: https://developers.google.com/search/docs/appearance/structured-data/sd-policies
- IndexNow can notify participating search engines about changed URLs, but an accepted submission only confirms receipt: https://www.indexnow.org/documentation
